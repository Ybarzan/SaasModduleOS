1. POUR QUI LE FONT-ILS ? (Cibles principales)
Fabricants (industriels, producteurs de biens)

Grossistes (distributeurs, négociants)

Entreprises B2B ayant une activité logistique régulière (expéditions nationales et internationales)

Utilisateurs finaux au sein de ces entreprises : responsables logistiques, équipes expédition, services achats, équipes commerciales, gestionnaires d'entrepôt

Clients indirects : les destinataires finaux (clients des fabricants/grossistes) qui reçoivent les notifications de suivi

2. QUOI FONT-ILS ? (Périmètre fonctionnel détaillé)
A. Centralisation et unification des données

Rassemblent toutes les informations de transport dans un seul tableau de bord (web + mobile)

Éliminent la navigation sur les multiples portails de transporteurs

Centralisent les grilles tarifaires, les délais de transit, les documents, les statistiques et les notifications

B. Intégration technique

Se connectent aux ERP/WMS existants (Microsoft Business Central, Odoo, Magento, WooCommerce, Directo, Erply, iScala, Ongoing Warehouse...)

Permettent un démarrage manuel sans intégration (mode "saisie manuelle")

Offrent plus de 1 500 intégrations "plug-and-play" avec des transporteurs

Fournissent une API ouverte pour des connexions personnalisées

C. Comparaison et aide à la décision

Comparent les tarifs négociés par l'entreprise (pas de prix imposés par un intermédiaire)

Comparent les délais de transit entre transporteurs

Comparent l'empreinte CO₂ estimée pour chaque expédition

Permettent de demander des prix "spot" ponctuels aux transporteurs

D. Réservation et exécution

Réservent le transporteur choisi directement depuis l'interface

Automatisent la réservation via des règles prédéfinies (ex : toujours le moins cher, le plus rapide, etc.)

Génèrent automatiquement les documents : étiquettes, lettres de voiture (CMR), e-Waybill, DGD (marchandises dangereuses), déclarations d'exportation

Gèrent les expéditions aussi bien à l'achat qu'à la vente (flux entrants et sortants)

E. Suivi et visibilité en temps réel

Suivent toutes les expéditions en un seul endroit (statuts, jalons, géolocalisation)

Surveillent la collecte et l'arrivée des marchandises

Alertent automatiquement sur les retards ou anomalies

F. Communication et notifications

Envoient des notifications personnalisées et "brandées" (couleurs, logo de l'entreprise)

Informent les équipes internes : achats, vente, entrepôt

Informent les clients et fournisseurs (lien de suivi, quel que soit le transporteur)

Envoient des rapports quotidiens sur les performances et les retards

G. Gestion durable

Calculent et affichent l'estimation des émissions de CO₂ pour chaque expédition

Aident à choisir des options de transport moins polluantes

H. Contrôle financier et administratif

Comparent les factures des transporteurs avec les montants pré-calculés

Fournissent des statistiques et indicateurs de performance (KPI logistiques)

Permettent une gestion centralisée des coûts de transport

3. COMMENT LE FONT-ILS ? (Mécanismes et modes opératoires)
1. Architecture technique

Solution SaaS basée sur le cloud

Accessible via application web et application mobile

API REST pour connecter des systèmes sur mesure

2. Intégration avec les systèmes existants

Récupèrent automatiquement les commandes (ventes/achats) depuis l'ERP

Synchronisent les données utilisateurs, produits, adresses, etc.

Mode "plug-and-play" pour les transporteurs (pas de développement lourd)

Possibilité de connecter les systèmes via des connecteurs préconstruits

3. Fonctionnement pour l'utilisateur

L'utilisateur se connecte à son tableau de bord

Il voit ses commandes à expédier (importées automatiquement)

Il compare les offres de transport (prix, délais, CO₂)

Il sélectionne un transporteur et réserve en 1 clic

Il suit l'expédition en temps réel depuis le même écran

Il reçoit ou envoie des notifications automatisées

4. Gestion des transporteurs

L'entreprise conserve ses propres tarifs négociés (pas de surfacturation)

L'entreprise choisit quels transporteurs activer sur son compte

Les transporteurs sont intégrés via API/EDI, sans intervention manuelle

Possibilité d'ajouter un transporteur non listé gratuitement

5. Mode de déploiement

Configuration initiale assurée par l'équipe Cargoson (prise en charge de l'engagement)

Démarrage possible en mode manuel pour tester

Montée en puissance progressive vers l'automatisation complète

Accompagnement et support inclus

6. Personnalisation

Notifications aux couleurs de l'entreprise (branding)

Règles de réservation automatisées paramétrables

Tableau de bord adaptable aux besoins de l'utilisateur

4. VALEUR AJOUTÉE UNIQUE (Différenciateurs clés)
✅ Pas d'intermédiaire : l'entreprise garde le contrôle total sur ses tarifs et ses relations transporteurs (pas de frais de courtage)

✅ Neutralité transporteur : pas de transporteur imposé, tous peuvent être intégrés

✅ Centralisation absolue : toute la logistique dans un seul outil (fini les portails multiples)

✅ Facilité d'utilisation : configuration simple, prise en main rapide

✅ Approche durable : estimation CO₂ intégrée pour chaque décision

✅ Flexibilité technique : fonctionnement avec ou sans intégration ERP

✅ Mise en œuvre rapide : "plug-and-play" avec plus de 1 500 transporteurs

✅ Communication simplifiée : clients et fournisseurs informés automatiquement

# IncoKalk — Roadmap Complet des Manques

> Dernière mise à jour : 23/07/2026

## P0 — Urgent (Semaines 1-4) — Fondations douanes françaises

### 1. Base tarifaire TARIC réelle
- [ ] Intégrer les données TARIC (TARIF INTégré de la Communauté) via l'API ouverte de la DGDDI / EUR-Lex
- [ ] Mapper les codes SH aux droits ad valorem + droits spécifiques + contingents
- [ ] Stocker les taux par pays d'origine x code HS x régime tarifaire
- [ ] Remplacer les 9 moyennes chapitre actuelles par des taux réels
- [ ] Gérer les droits antidumping et compensateurs
- [ ] Cache Redis avec TTL 24h sur les taux TARIC

### 2. Régimes préférentiels EU (APE/AGP)
- [ ] Intégrer les accords de libre-échange EU par code HS (1400+ accords bilatéraux)
- [ ] Vérification Rules of Origin (origin criteria: WH, WO, PE, CTH, CTSH)
- [ ] Calcul du droit préférentiel vs droit MFN (Most Favoured Nation)
- [ ] Gestion des certificats d'origine EUR.1 / eurs.1
- [ ] Logique de cumul bilatéral, cumul régional (ASEAN, etc.)

### 3. TVA intracommunautaire
- [ ] Règles de reverse charge pour les acquisitions intracom
- [ ] Taux réduits, super-réduits, exonérations par pays EU
- [ ] TVA à l'importation (TAI — Taxe Assise à l'Importation)
- [ ] Numéro de TVA intracommunautaire (VIES) validation
- [ ] Calcul TVA sur marge (régime de la marge pour les biens d'occasion)

### 4. EORI
- [ ] Stockage et validation du numéro EORI (format: FR + 15 chiffres)
- [ ] Vérification en ligne via le portail EU EORI
- [ ] Association EORI ↔ Company
- [ ] Obligation : chaque opérateur doit avoir un EORI pour déclarer

### 5. Facture douanière
- [ ] Génération de facture douanière (commercial invoice adaptée pour la douane)
- [ ] Champs requis : description marchandise, HS code, valeur CIF/FOB, origine, pays d'destination
- [ ] Multi-devise avec conversion au taux BCE du jour
- [ ] Export PDF conforme aux exigences DGDDI

## P1 — Haute Priorité (Semaines 5-10) — Documents de déclaration

### 6. Document unique de douane (DUD/DAU/SAD)
- [ ] Génération du DAU (Document Administratif Unique) au format XML EDIFACT
- [ ] Types : import (DAU IMP), export (DAU EXP), transit (T1, T2)
- [ ] Champs obligatoires : code bureau, régime douanier, code douanier, valeur en douane, origine
- [ ] Mode brouillon → prêt → soumis → validé → archivé
- [ ] Export PDF + XML pour soumission électronique

### 7. Déclaration d'échanges de biens (DEB/Intrastat)
- [ ] DEB expéditions (vendeur EU → acheteur hors EU)
- [ ] DEB introductions (acheteur EU ← vendeur hors EU)
- [ ] Intrastat pour les échanges intra-EU ( flux d'arrivée / flux de départ)
- [ ] Seuil de déclaration (460 000 € pour la France en 2026)
- [ ] Codes nomenclature combinée 8 chiffres
- [ ] Export DEB au format XML (DGDDI / NETT declared)

### 8. ICS2 (Import Control System 2)
- [ ] Pré-déclaration de sécurité pour les importations par voie maritime
- [ ] Données requises : shipper, consignee, HS 6-digit, poids, conteneur
- [ ] Soumission au format ICS2 XML via le portail douanier
- [ ] Statut : envoyé, accepté, rejeté, en attente

### 9. AES / EXS (Export)
- [ ] Déclaration de sortie (AES — Automated Export System)
- [ ] EXS (Exit Summary Declaration) pour les marchandises quittant l'EU
- [ ] Intégration avec le guichet unique CDS (Customs Declaration Service)
- [ ] Statut de déclaration export : brouillon, soumise, validée

### 10. Workflow de dédouanement
- [ ] Pipeline complet : Pré-déclaration → Déclaration → Vérification → Dédouanement → Livraison
- [ ] Statuts : DRAFT → SUBMITTED → UNDER_REVIEW → CLEARED → RELEASED → REJECTED
- [ ] Alertes automatiques : document manquant, HS code incohérent, valeur douteuse
- [ ] Historique complet par shipment
- [ ] Tableau de bord des déclarations en cours
